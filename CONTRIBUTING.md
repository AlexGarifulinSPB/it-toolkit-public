# Как добавлять контент

## Общие правила

1. **Один файл — одна сущность.** Один агент в одном файле, один чек-лист в одном файле.
2. **Имена файлов — kebab-case, английские.** `agent-diagnet.md`, не `Агент Диагностика.md`.
3. **Никаких клиентских данных.** Перед коммитом запускается линтер секретов — он отловит явные пароли/IP/email, но финальная ответственность на тебе.
4. **Markdown** — основной формат. Скрипты — в своих расширениях.

## Добавить агента

1. Скопируй `agents/_template.md` → `agents/agent-<имя>.md`.
2. Обязательные секции: `Назначение`, `Что нужно на вход`, `Процедура`, `Формат вывода`, `Ограничения`.
3. Добавь строку в таблицу `agents/README.md`.
4. Коммит: `feat(agents): add <имя> agent`.

## Добавить чек-лист

1. Имя: `checklists/checklist-<тема>.md`.
2. Структура: цель → предусловия → шаги (нумерованные) → проверка результата → откат.
3. Каждый шаг — действие в одном предложении. Не «настроить firewall», а «открыть TCP/443 в zone WAN на адрес X».

## Добавить скрипт

1. Положи в `scripts/<язык>/`.
2. Шапка-комментарий обязательна:
   ```
   # Назначение: что делает
   # Использование: как запускать
   # Требования: версия PS, утилиты, права
   # Опасные операции: какие, как откатить
   # Автор/дата
   ```
3. **Идемпотентность** где это уместно: повторный запуск не должен ломать систему.
4. Все клиент-специфичные значения — переменные сверху файла, помеченные `# CHANGE ME:`.

## Коммиты

Conventional Commits, коротко:
- `feat(agents): …` — новый агент
- `feat(checklists): …` — новый чек-лист
- `feat(scripts): …` — новый скрипт
- `fix(…)`: правка
- `docs(…)`: правка документации
- `refactor(…)`: переделка без изменения смысла

## Перед push'ем

- `markdownlint **/*.md` (или дождись CI)
- Прогон `gitleaks detect` локально, если правил руками
- Проверь, что не добавил случайно что-то из приватного репо
